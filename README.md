# sources.avar.me

Хранилище исходных данных для проектов [avar.me](https://avar.me): словари, книги, текстовые корпусы. Публикуется через GitHub Pages: <https://sources.avar.me>.

Это **источник правды** (single source of truth) для всех остальных сайтов и инструментов экосистемы avar.me. Файлы в `data/` нужно править здесь — пересборка автоматически обновит и сам сайт, и зависимые проекты, которые подтянут данные при следующей сборке.

## Что внутри

- **`sources.json`** — реестр всех исходников: id, заголовок, описание, формат, путь, версия, лицензия.
- **`data/`** — собственно данные. Сейчас два словаря в `jsonl`:
  - `av-ru.jsonl` — сводный аварско-русский (22 871 статья), результат сборки
  - `av-ru.2006.jsonl` — словарь под редакцией М. М. Гимбатова (22 836 статей)
  - `av-ru.avar.me.jsonl` — дополнения avar.me (35 статей)
  - `ru-av.jsonl` — русско-аварский (~38 800 статей)
- **`books/`** — оригинальные PDF (сканы словарей, на основе которых сделана jsonl-нормализация).
- **`src/build_site.py`** — генератор статического сайта из `sources.json` + `data/` + `books/`.
- **`docs/`** — собранный сайт (артефакт сборки; не редактировать вручную).

## Использование

### Просто почитать словари

Откройте <https://sources.avar.me> и переходите в нужный словарь. Навигация по алфавиту, как в книге.

### Сообщить об ошибке

Заметили опечатку, неверный перевод, кривое расширение формы? Напишите в Telegram-чат [@avarme_chat](https://t.me/avarme_chat) — там обсуждаем правки. Под каждой статьёй на сайте есть ссылка «сообщить о неточности», которая открывает чат с готовым сообщением.

Канал [@avarlangme](https://t.me/avarlangme) — для новостей проекта.

### Скачать сырые данные

Прямые ссылки (стабильные, на них опираются другие проекты):

- <https://sources.avar.me/data/av-ru.jsonl>
- <https://sources.avar.me/data/ru-av.jsonl>
- <https://sources.avar.me/sources.json>

### Подтянуть данные в свой проект

```bash
curl -fsSL https://sources.avar.me/data/av-ru.jsonl > av-ru.jsonl
```

Так делают [forms](https://github.com/avar-me/forms), [avar.me](https://avar.me), `corrector` и прочие — данные **не дублируются** между проектами.

## Формат данных (jsonl)

Полные схемы словарей:

- `av-ru`: [`schemas/av-ru.md`](schemas/av-ru.md), JSON Schema [`schemas/av-ru.schema.json`](schemas/av-ru.schema.json);
- `ru-av`: [`schemas/ru-av.md`](schemas/ru-av.md), JSON Schema [`schemas/ru-av.schema.json`](schemas/ru-av.schema.json).

Проверка текущего `ru-av` и сравнение с подготовленной новой редакцией:

```bash
python3 scripts/ru_av_intake.py validate data/ru-av.jsonl
python3 scripts/ru_av_intake.py compare data/ru-av.jsonl incoming/ru-av.jsonl
```

Одна строка = одна статья словаря. Пример:

```json
{
  "word": "бакъ",
  "stress": 1,
  "stem": "бакъ",
  "forms": ["бакълъи", "бакълъул"],
  "senses": [
    {
      "text": "солнце",
      "labels": ["существительное"],
      "examples": [
        {"av": "бакъ борхьинчӏого", "ru": "до захода солнца"}
      ]
    }
  ],
  "see_also": [{"target": "бакъул", "kind": "see"}]
}
```

Поля (необязательные могут отсутствовать):

| Поле | Описание |
|------|----------|
| `word` | Заглавное слово. |
| `stress` | Позиция ударной гласной (1-based) или отсутствует. |
| `stem` | Основа для раскрытия форм. |
| `forms` | Раскрытые словоформы. |
| `gender_forms` | Формы по грамматическим классам/родам (`av-ru`). |
| `spelling_forms` | Варианты написания одной лексемы; включает текущее `word` первым (`av-ru`). |
| `senses[]` | Значения. У каждого: `text`, `comment`, `labels[]`, `examples[]`. |
| `senses[].examples[]` | `{av, ru, labels?}` — примеры с переводом. |
| `see_also[]` | Ссылки «см.» / «от …»: `{target, kind}`. |

## Сборка сайта

```bash
./build.sh
```

Локально проверить:

```bash
python3 -m http.server -d docs 8000
# открыть http://localhost:8000
```

Деплой автоматический: `git push origin main` → GitHub Actions собирает `docs/` и публикует на GitHub Pages.

## Сборка аварско-русского словаря

Правки статей вносите в `data/av-ru.2006.jsonl` или `data/av-ru.avar.me.jsonl`
по происхождению статьи. `data/av-ru.jsonl` хранится в Git для потребителей,
но собирается автоматически; напрямую его не редактируйте.

```bash
python3 src/build_dictionaries.py
python3 -m unittest discover -s tests
```

`./build.sh` и прямой запуск `python3 src/build_site.py` сначала собирают словарь.
В `dictionary-build.json` входные файлы перечислены от высшего приоритета
к низшему: 2006, затем avar.me. Для каждого точного `word` выбирается первый
источник, содержащий это слово, со всеми его статьями (включая омонимы).
Значения отдельных статей между источниками не смешиваются.

Сводный файл стабильно сортируется по аварскому алфавиту, тем же алгоритмом,
что и сайт: диграфы считаются отдельными буквами. Статьи с одинаковым `word`
сохраняют порядок внутри выбранного источника. Ручные правила размещения
дополнений не нужны.

Каждая статья имеет `source`: `av-ru.2006` для словаря 2006 года;
существующие `avar.me.2026` у дополнений сохранены. Чтобы подключить словарь
1967 года, добавьте его файл и запись в `sources.json`, затем включите файл
в `inputs` на нужной позиции приоритета и пересоберите словарь.

## Контрольные суммы опубликованных файлов

При сборке вычисляется SHA-256 точных байтов опубликованных файлов данных,
оригиналов и `sources.json`. Главная страница показывает хеш каждого файла
данных; полное значение можно раскрыть и выделить. Рядом с файлами публикуются
`<имя файла>.sha256`, а в корне сайта — `SHA256SUMS` со всеми суммами.
В `build.json` хеш данных доступен как `stats[<id>].sha256`.

Для проверки скачайте файл и соответствующий `.sha256` в одну папку:

```bash
shasum -a 256 -c av-ru.jsonl.sha256
```

Общий `SHA256SUMS` использует пути от корня сайта (`data/...`, `books/...`).
