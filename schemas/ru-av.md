# Схема `data/ru-av.jsonl`

Машиночитаемая схема одной статьи: [`ru-av.schema.json`](ru-av.schema.json). Текущий файл можно проверить автономной утилитой:

```bash
python3 scripts/ru_av_intake.py validate data/ru-av.jsonl
```

Одна строка JSONL — один JSON-объект словарной статьи. Строки сериализуются как `json.dumps(obj, ensure_ascii=False)` с обычными пробелами после `:` и `,`.

## Направление перевода и языки полей

В отличие от `av-ru`, заголовок здесь русский, а основной перевод — аварский.

| Путь | Содержание | Язык |
|---|---|---|
| `word`, `stem`, `forms[]` | заголовок, основа и формы | русский |
| `senses[].text` | перевод или толкование | аварский |
| `senses[].examples[].ru` | русская исходная фраза или перевод | русский |
| `senses[].examples[].av` | аварский пример или перевод | аварский |
| `labels[]` | грамматические, стилистические и отраслевые пометы | русский |
| морфологические ссылки, `see_also[].target` | целевое заглавное слово | русский |
| `see_also[].comment` | русский контекст ссылки | русский |

`precomment` и `comment` — наследованные пояснения исходного словаря. В текущих данных они обычно аварские, но встречаются русские грамматические пометы и смешанные строки. Поля `comment_lang` в текущем формате нет: при обновлении язык этих пояснений нельзя массово угадывать или менять без отдельного решения.

## Статья

Обязательные поля текущего формата:

- `word` — русское заглавное слово;
- `forms[]` — непустой массив русских форм; сейчас заголовок входит в `forms` каждой статьи.

Необязательные поля:

- `stress` — 1-based позиция ударной гласной в `word`;
- `homonym` — номер омонима, если он явно дан источником;
- `stem` — русская основа, часто прописными буквами;
- `labels[]` — пометы всей статьи;
- `precomment` — общее предварительное пояснение;
- `exclamation` — форма междометного восклицания;
- `senses[]` — значения;
- `see_also[]` — связи с другими русскими статьями.

Чистая служебная статья может не иметь `senses` и `see_also`: текущий файл содержит такие записи, поэтому структурная схема их допускает и сравнительный отчёт считает отдельно.

## Значение (`senses[]`)

- `text` — аварский перевод или толкование;
- `precomment` — пояснение перед переводом;
- `labels[]` — русские пометы;
- `forms[]` — формы конкретного значения;
- `comment` — пояснение в языке источника;
- `examples[]` — примеры;
- `genitivefrom`, `dativefrom`, `locativefrom`, `pluralfor` — типизированные ссылки на русскую базовую статью;
- `refwordnum` — номер значения целевой статьи.

Значение может быть чистой грамматической отсылкой и не иметь `text`.

## Пример (`senses[].examples[]`)

Допустимые поля:

- `av` — аварская сторона примера;
- `ru` — русская сторона;
- `labels[]` — русские пометы;
- `comment` — пояснение.

Исторические данные содержат односторонние примеры, поэтому схема требует хотя бы одно из `av` или `ru`, но не требует оба одновременно. Отсутствие одной стороны должно отдельно попадать в отчёт качества и сравнение редакций.

## Связь (`see_also[]`)

- `target` — русский заголовок цели;
- `kind: "see"` — «см. также»;
- `kind: "from"` — форма или производное от цели;
- `refwordnum` — номер значения цели;
- `comment` — русский контекст, к которому относится ссылка.

## Идентичность и повторяющиеся статьи

`word` и даже пара `(word, homonym)` **не являются уникальным идентификатором**. В текущем файле есть повторяющиеся записи без номера омонима. Поэтому импортёр не должен:

- загружать JSONL в словарь `word -> entry`;
- склеивать одинаковые заголовки;
- считать вторую запись автоматическим дублем;
- сопоставлять старую и новую редакции только по номеру строки.

Утилита приёмки сначала сопоставляет полностью одинаковые статьи как мультимножество внутри группы `(word, homonym)`, а оставшиеся записи пары сравнивает в стабильном порядке. Несопоставленные записи считаются добавленными или удалёнными.

## Порядок ключей

Рекомендуемый порядок для читаемых диффов:

- статья: `word → stress → homonym → stem → forms → labels → precomment → exclamation → senses → see_also`;
- значение: `text → precomment → labels → forms → морфологические ссылки → refwordnum → comment → examples`;
- пример: `av → ru → labels → comment`;
- связь: `target → kind → refwordnum → comment`.

## Приёмка новой редакции

Новый файл сначала кладётся вне `data/ru-av.jsonl`, например `incoming/ru-av.jsonl`, и проверяется без замены источника правды:

```bash
python3 scripts/ru_av_intake.py validate incoming/ru-av.jsonl
python3 scripts/ru_av_intake.py compare data/ru-av.jsonl incoming/ru-av.jsonl
```

Отчёт должен быть просмотрен до решения о полной замене или выборочном объединении. Особое внимание:

1. удалённым статьям, значениям и примерам;
2. изменению количества повторяющихся `(word, homonym)`;
3. новым или исчезнувшим полям;
4. односторонним примерам;
5. изменению `stress`, `homonym`, `forms` и `see_also`;
6. сохранению всех строк при полной замене.
