# Унификация морфологических stub’ов в av-ru

Статус: **отложено** (2026-07-19). Правки блока 2 (понудительные) были внесены
в рабочее дерево и **откачены** — решение не принималось. Этот файл — память
задачи: findings, предлагаемый канон, примеры разной структуры JSON для сверки
в потребителях (`forms`, `avar.me`, `corrector`, …).

Источник: `data/av-ru.jsonl` only (`av-en` в этом потоке не трогаем).

---

## 1. Задача

Привести к единому виду статьи-указатели и морфопометы вида:

- родительный / другие падежи («род. пад.», «родительный падеж», «от X; род.» …);
- масдар (в т.ч. «мазд. понудительная форма»);
- понудительная форма (префикс в `text` vs `labels` + `forceto`);
- абстрактные `-лъи`, прочие `от 'X'`.

Сейчас большая часть уже единообразна за счёт машинных полей
(`genitivefrom`, `masdarfrom`, `forceto`, …), но comment/text/`form`/`see_also`
расходятся — потребители, которые читают только `text`/`comment`, показывают
разное.

---

## 2. Findings (инвентаризация 2026-07-19)

### Родительный

| Паттерн | Объём (порядок) | Пример |
|---------|-----------------|--------|
| `genitivefrom` + `comment: "родительный падеж"` | ~1628 | `абазиназул` |
| `comment: "родительный падеж от 'X'"` (+/− `genitivefrom`) | ~13–14 | `измуралъул`, `афгъаназул` |
| `comment: "от 'X'; род."` | 1 | `чотӏрол` |
| `casefrom` + `comment: "падеж"` (+ иногда `text: "род."`) | 6 | `кепкил`, `дивизиялъул`, `чол` |

Недавнее решение в `CLAUDE.md`: для stub предпочтительна полная формула
`родительный падеж от 'X'` (+ `genitivefrom` + `see_also` kind `from`).

### Масдар

| Паттерн | Объём | Пример |
|---------|-------|--------|
| `labels` + `masdarfrom` / `masdarforceto`, без text | ~2877 | `аби`, `абизаби` |
| `form: масдар`, **пустые `senses`**, labels на уровне статьи | ~308 | `ахӏдезаби` |
| `text: "мазд. понудительная форма"` / «масдар понудительной формы» | 3 | `цӏикӏкӏинаби` |

«Масдар от …» в comment **не** используется: база в `masdarfrom` / `masdarforceto`.

### Понудительная

| Паттерн | Объём | Пример |
|---------|-------|--------|
| `labels: ["понудительная форма"]` + `forceto` + `see_also` from | ~568+ | `алхинабизе` |
| label в labels, глосса без префикса (иногда без `forceto`) | много | `капкикълъизабизе` |
| `text: "понудительная форма от"` (обрывок) | 7 | `какизабизе` |
| `text` начинается с «понудительная форма …» (префикс + глосса) | ~15 | `камиллъизабизе` |

### Другие падежи (`dativefrom` / `ergativefrom` / `locativefrom` / `ablativefrom`)

Обычно `comment: "<падеж>"` **без** `от 'X'`, хотя `*from` есть (~30).
Есть уже полные формулы (`бетӏерлъиялда`, `диде`, `сундухъ`) и аббревиатуры
(`дуде`: `от 'мун'; направ. п.`; `дилъ`: `2; падеж`).

Осторожно: у части местоимений (`гъол`, `лъол`, …) поле `locativefrom` есть, но
comment **не** падежный stub — при унификации не переписывать вслепую.

### Уже единообразно

- абстрактные `-лъи`: `абстрактное имя от 'X'` (~30);
- производные указатели: `comment: "от 'X'"` + `see_also` from (напр. `бакӏалда`).

---

## 3. Предлагаемый канон (не применён)

1. **Родительный stub:**  
   `genitivefrom: "X"` + `comment: "родительный падеж от 'X'"` + `see_also` kind `from`.  
   Не: голое `родительный падеж`, не `от 'X'; род.`, не `падеж`/`род.` через `casefrom`.

2. **Другие падежи с `*from`:**  
   `comment: "<имя падежа> от 'X'"` (составные: `от 'A', 'B'`).  
   Семантические хвосты сохранять (`без мужчин; эргативный падеж от '…'`).

3. **Масдар:** только структура (`labels` + `masdarfrom`/`masdarforceto`);  
   article-level labels без sense — отдельный проход (~300); убрать `мазд.` из text.

4. **Понудительная:** `labels` + `forceto` + `see_also` from; глоссу без префикса
   «понудительная форма»; stub без глоссы — `comment: "от 'X'"` без text;
   `form: "понудительная форма"`.

5. **`av-en` не трогаем.**

### Предлагаемый порядок работ

1. Родительный (~1628 + хвост) — отложено.  
2. Понудительные в text (~24) — **пробовали, откатили**.  
3. Масдар-outliers (~300 пустых senses + 3 мазд.) — отложено.  
4. Прочие падежи (~30) + `casefrom`→родительный — отложено.

Черновик правок блока 2 (для возврата): см. переписку 2026-07-19; суть —
7 stub’ов + ~13 с префиксом в text + 3 масдара каузатива → канон п.4.

## 4. Примеры: одна сущность — разный JSON

Ниже реальные статьи из `data/av-ru.jsonl` (снимок на момент записи файла).
Имеет смысл открыть те же headword’ы в UI потребителей и сравнить, что
видит пользователь, когда:

- глосса только в машинном поле (`masdarfrom` / `genitivefrom`), а `text` пуст;
- «перевод» — на самом деле морфопомета в `text`;
- comment короткий vs полный с базой в кавычках;
- labels на статье vs в `senses[]`;
- `see_also` kind `see` vs `from`.

## 5. Когда вернуться

1. Пройти примеры §4 в потребителях (что видно при пустом `text`, при `мазд.` в text, …).  
2. Зафиксировать канон (особенно: дублировать ли базу в comment, если уже есть `*from`).  
3. Применять блоками с апрувом; changelog + при необходимости `changelog/ГГГГ-ММ-ДД-…md`.  
4. Не зеркалить в `av-en`.
