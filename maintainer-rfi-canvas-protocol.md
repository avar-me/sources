# Protocol: maintainer-RFI разбор через Cursor Canvas

**Audience:** агент (или человек), который разбирает пачку замечаний из
`av-ru-maintainer-rfi.jsonl` (dial-eval / `llm-av-ru-review`) вместе с
мейнтейнером.

**Статус:** нормативный, evergreen — читать **перед** каждым новым раундом.
Ссылка из [`CLAUDE.md`](CLAUDE.md) §«Maintainer-RFI (dial-eval)».

Раунд 2026-07-19 (canvas `av-ru-maintainer-rfi-4-review`) зафиксировал
рабочую схему ниже. Не возвращаться к простыне в чате без явных «сейчас →
предложение» и без разбиения по типам.

---

## 1. Цель

Быстро согласовать с мейнтейнером каждую строку RFI **до** записи в
`data/*.jsonl`:

1. что именно сейчас в статье;
2. что предлагаем поставить;
3. к какому типу относится правка (отклонено / опечатка / структура);
4. как будет выглядеть весь JSON статьи после правки.

Данные в репозиторий пишем **только после** явного «да» / «коммить» /
«commit, push». Молчание или правка одного пункта — не апрув на остальные.

---

## 2. Вход

- Рабочий файл: `av-ru-maintainer-rfi.jsonl` в корне `sources`
  (не источник правды; после раунда очищается до пустого файла, как в
  коммитах dial-eval).
- Источник правды для сверки: `data/av-ru.jsonl`.
- **`data/av-en.jsonl` в этом потоке не трогаем** — английский словарь
  ведут другие мейнтейнеры; dial-eval RFI правит только av-ru (и changelog).
- Одно замечание = одна логическая правка; у одного `word` может быть
  несколько строк (разные `path` / поля).

Нумерация в canvas **стабильная на весь раунд** (`#1…#N`), даже если
фильтр скрывает часть строк.

---

## 3. Canvas — обязательный артефакт раунда

### 3.1. Где лежит

Cursor Canvas: файл `.canvas.tsx` в

`~/.cursor/projects/<workspace>/canvases/`

Имя вида `av-ru-maintainer-rfi-<N>-review.canvas.tsx`.

Canvas **не** коммитится в `sources` (это UI раунда). В changelog раунда
достаточно упомянуть имя canvas.

Импорты — только из `cursor/canvas`. Данные (строки RFI, JSON статей)
вшиваются inline: никакого `fetch()`.

### 3.2. Три таблицы по типу

Не один общий список с фильтром «тип», а **три отдельные секции/таблицы**:

| Таблица | Когда |
|---|---|
| **Отклонено** | False positive: данные не трогаем (классное согласование, словарная поэтика, уже отклоняли и т. п.) |
| **Опечатки** | Замена текста без смены схемы статьи (буквы, согласование, хвост «; не», диапазон в comment и т. п.) |
| **Структура** | POS/form, `forms[]`, перенос в `comment`/`labels`, stub «от» → comment + `see_also` from, удаление sense-пустышки, rename headword+forms |

У каждой строки поле `cat`: `"отклонено" | "опечатка" | "структура"`.

Статы сверху: сколько в каждой корзине.

### 3.3. Колонки строки

Обязательные колонки:

`#` · `слово` · `поле` · `замечание` · **сейчас** · **предложение** · кнопка `json`

Правила для «сейчас» / «предложение»:

1. **Всегда** заполнять явную пару было/стало. Прочерк «—» только у
   отклонённых (с пометкой вроде `— отклонено (FP, …)`).
2. Не оставлять `was === now`, если правка планируется — мейнтейнер не
   должен переспрашивать «а что ты предлагаешь?».
3. Ширина колонок «сейчас» и «предложение» **одинаковая**.
4. Подсветка diff — **только изменённые буквы** (char-level LCS / сегменты
   del/ins), не заливка всей ячейки. Полная заливка ячейки запрещена:
   на цифрах вроде `9 001` → `900 001` она маскирует разницу.

Для структурных правок в «сейчас/предложение» допустим многострочный
краткий план:

```
text: …
comment: …
```

но без служебного мусора вроде `(+ see_also from)` — это заметки агента,
в итоговый `comment` статьи они **не** попадают.

### 3.4. JSON под строкой

По кнопке `json` (или аналогу) раскрывается **под этой же строкой**, не
карточка наверху списка:

1. блок **JSON сейчас** (текущая статья из `data/av-ru.jsonl`);
2. блок **JSON предложение** (статья после применения правки раунда).

Два JSON подряд, сверху вниз. Для омонимов / двух статей с одним `word`
(пример: `захӏмат` сущ. vs наречие) индекс JSON — **по номеру строки**
(`BY_N` / `BY_N_NEW`), не по одному ключу `word`.

Закрытие — повторный клик или кнопка «закрыть».

### 3.5. Итерации с мейнтейнером

Пока идёт разбор:

- правки формулировок «предложение» и `BY_N_NEW` — в canvas;
- в `data/*.jsonl` ещё не пишем;
- мейнтейнер правит формулу голосом («родительный падеж от 'X'», «букв. в
  comment», «не переставляй слова в примере») → агент сразу обновляет
  строку canvas и новый JSON.

Типичные ловушки, уже пойманные в раунде 4:

- не выдумывать перестановку слов в av-примере, если RFI просил только
  убрать повтор;
- не подставлять в `comment` статьи текст из колонки-подсказки canvas;
- для genitive stub предпочитать
  `comment: "родительный падеж от 'X'"`
  (а не краткое `от 'X'; род.`), плюс `genitivefrom` / `see_also` kind
  `from` как было;
- `; . …` + `comment: "буквально"` → вынести дословное в
  `comment: "букв. …"`, основной перевод оставить в `text`.

---

## 4. После апрува: запись в данные

Порядок:

1. Применить все строки с `cat != отклонено` к `data/av-ru.jsonl`
   (только затронутые статьи; не переписывать весь jsonl «для красоты»
   separators/порядка ключей — иначе гигантский бессмысленный дифф).
2. **`data/av-en.jsonl` не менять** в dial-eval раунде.
3. Запись в [`CHANGELOG.md`](CHANGELOG.md) сверху + подробный файл
   `changelog/ГГГГ-ММ-ДД-av-ru-maintainer-rfi-<N>.md` с разбивкой
   Отклонено / Опечатки / Структура.
4. Очистить `av-ru-maintainer-rfi.jsonl` (пустой файл, как после прошлых
   dial-eval коммитов).
5. `git commit` + `git push` — только после явной команды мейнтейнера.

Схема статей (stubs «от», `букв.`, labels) — по разделу «Решённые вопросы»
в [`CLAUDE.md`](CLAUDE.md). Для родительного падежа в comment —

```json
{"genitivefrom": "измур", "comment": "родительный падеж от 'измур'"}
```

---

## 5. Чек-лист перед сдачей раунда

- [ ] У каждой не-FP строки в canvas заполнены разные «сейчас» и «предложение».
- [ ] Три таблицы на месте; FP не смешаны с опечатками.
- [ ] Diff подсвечивает только изменённые буквы.
- [ ] `json` показывает старый и новый JSON **под** строкой; омонимы не
      перепутаны.
- [ ] В предлагаемых `comment` нет хвостов `(+ see_also …)`.
- [ ] Мейнтейнер явно апрувнул (или «коммить» / «commit, push»).
- [ ] В `data/` правлен только `av-ru.jsonl` (нужные строки); **av-en не трогали**.
- [ ] `CHANGELOG.md` + `changelog/…-maintainer-rfi-….md`.
- [ ] `av-ru-maintainer-rfi.jsonl` очищен.

## 6. Связь с другими потоками RFI

| Поток | Протокол |
|---|---|
| multilang `issues.av-ru.jsonl` / expert-review FP | [`expert-review-protocol.md`](expert-review-protocol.md) |
| dial-eval `av-ru-maintainer-rfi.jsonl` | **этот файл** |

Не смешивать форматы rejected-файлов expert-review с canvas dial-eval:
у dial-eval FP фиксируются в таблице «Отклонено» canvas + кратко в
changelog раунда (без обязательного `## #NNN` блока expert-review), если
отдельно не попросили завести rejected-файл.
