# Поиск и исправление ошибок av-ru.1936

Согласованный порядок работы, 28 октября 2026 года.

## Основной метод

Ищем инверсии соседних заголовков по историческому алфавиту, затем разбираем каждую подозрительную пару в контексте. Двигаемся по порядку статей оригинала; новые кандидаты на уже пройденных страницах также возвращаются в работу. Не заменяем этот подход обязательной сплошной вычиткой всего словаря.

1. Запустить аудит порядка и открыть пару вместе с соседними статьями. Инверсия — повод для сверки, а не готовая ошибка и не команда пересортировки.
2. Изучить статью в HTML/DOCX: варианты заголовка, квадратные скобки с формами, падежные метки, происхождение, примеры и ссылки. Несогласованность заголовка с формой внутри статьи помогает восстановить букву.
3. Для проверки начертания свериться с оригинальным PDF. PDF не редактировать. При необходимости сопоставить значение и основу со словарём 2006 года, сохраняя историческую латиницу 1936 года.
4. Исправить подтверждённую ошибку точечно и синхронно в HTML и DOCX, включая затронутые формы, примеры и ссылки. Не заменять похожую букву глобально: q/ꝗ/ƣ, h/ħ/ḩ, l/ļ/ł, s/ꞩ/ş, x/x̨/x̵, z/ƶ/ⱬ различаются по контексту. Настоящее o+q не равно распавшейся ƣ.
5. Если написание и перестановка подтверждаются печатью, сохранить исходный порядок и записать пару в `av-ru.1936-order-reviewed.json`. Неясное чтение оставить кандидатом; при необходимости запросить помощь пользователя. Типографскую ошибку отличать от OCR и документировать основание исправления.
6. Пересобрать JSONL, повторить аудиты порядка и алфавита, выполнить тесты. Проверить синхронность изменённых абзацев и отображение DOCX. В аварских полях сохраняются историческая латиница и допустимые знаки; кириллица и чужие графемы — отдельная эвристика OCR. Статус словаря остаётся `test`.
7. Записать объём изменений в CHANGELOG и подробные изменения полей в `changelog/`. Указывать отдельно число статей, число кандидатов-пар, подтверждённых печатных перестановок и оставшихся непроверенных пар. Затем коммит и push по поручению пользователя.

## Апостроф в сравнении

Апостроф нельзя удалять из ключа: это скрывает инверсии. Варианты `'`, `’`, `‘`, `ʼ`, `ʿ` унифицируются только для сравнения и учитываются как отдельный знак перед буквами. Само наличие апострофа не означает ошибку: в заимствованиях он может быть законным. Дефисы, регистр и ударения при сравнении игнорируются; для внутрисловных скобок учитываются оба варианта.

Контрольный пример: `assķo → ass’o → assosiasija` должен дать инверсию на `ass’o`. Форма `asslijab`, подтверждение пользователя и статья «аслу» в словаре 2006 года обосновали исправление типографской ошибки на `asslo, asslu`. После исправления инверсии нет. Этот случай закреплён тестом.

## Команды

```sh
python3 src/parse_zhirkov_1936.py
python3 src/audit_zhirkov_1936_order.py --report review/av-ru.1936-order.md
python3 src/audit_zhirkov_1936_alphabet.py --report review/av-ru.1936-alphabet.md --json review/av-ru.1936-alphabet.json
python3 -m unittest discover -s tests -p '*zhirkov*'
git diff --check
```

JSONL сериализуется через `json.dumps(..., ensure_ascii=False)` со стандартными пробелами. Правки не вносятся в `docs/` или в словари других источников.
